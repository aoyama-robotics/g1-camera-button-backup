# G1 無線接続の手順と記録 掲載候補

スマホのテザリングや持込ルータを使う際の接続確認と、既存資料に残る通信上の制限をまとめる候補です。掲載承認前のローカル案で、ネットワーク設定やG1操作は実行していません。

## 接続を確認する流れ

1. 開発PCとG1を、相互通信できる同じ無線ネットワークへ接続する構成を確認します。SSID・鍵・端末名・アドレスは各端末で管理し、この資料には記載しません。
2. 同じネットワーク内でもAPの端末間通信制限やマルチキャスト制限で通信できない場合があります。ネット接続の成否と、PCからG1への到達性を別々に確認します。
3. SSHなどの接続確認では、手元で確認した接続先・ユーザー名と既存の認証方法を使います。生の端末出力や接続設定は共有せず、確認日時・経路・到達可否だけを記録します。
4. 遠隔アクセスを使う構成では、既存の認証状態と経路を確認します。tailnet名・IP・鍵・端末識別子は掲載しません。この候補を作る際にログイン・設定変更は行っていません。
5. DDSを使う場合は、SSHが通ることだけで制御通信の成立とは判断しません。インターフェース、マルチキャスト到達性、受信間隔、通信断時の停止条件を別途確認します。

## 既存資料にある記録

`Common/network/WIFI_ROUTER.md` は2026-09-29更新で、持込ルータ配下での接続確認が記載されています。スマホテザリングの結果は `Navigation/nav2_stable/HANDOVER.md` と `QUESTIONS.md` に残っています。

- Wi-Fi省電力が有効なテザリングでは、心拍の経過時間が1秒を超え、`operator_lost` で停止した記録があります。
- 省電力を切った条件では、心拍の経過時間の中央値0.101秒、最大0.628秒、60秒中に0.5秒超え3回という記録があります。
- 既存資料には停止タイムアウトを延ばした暫定運用も記載されています。タイムアウト延長は通信断から停止までの遅延を増やすため、これを一般的な安全設定として流用しません。

これらは当時の資料の記録値です。今回の測定値ではなく、現在の無線機器・会場・G1構成での再現性や走行の安全性は確認していません。

## 掲載範囲

掲載する場合はこのような一般化した説明と確認結果だけに限定します。SSID、鍵、IP、端末名、tailnet識別子、認証情報、個人ネットワーク構成、生ログは含めません。元の接続資料をそのまま追加掲載する候補ではありません。
